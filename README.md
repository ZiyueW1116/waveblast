# Waveblast（波波气）

Waveblast 是一个服务器权威的多人同步回合制合成对战游戏原型。玩家每回合可以直接出招，或者消耗过去打出且尚未用于合成的招式实例，合成并立即打出一个新招式。

项目采用 TypeScript npm workspaces：

- `packages/game-engine`：不访问网络、数据库和时钟的纯函数规则引擎。
- `packages/game-data`：招式定义、完整合成表及派生属性。
- `packages/protocol`：浏览器与服务器共享的消息类型。
- `apps/server`：Fastify、Socket.IO、身份验证和活跃对局。
- `apps/web`：React 和 Vite 浏览器界面。

## 当前状态

这是便于继续验证规则的第一版原型，不应未经额外加固直接用于正式生产环境。

已经实现：

- 用户名密码注册和登录；密码使用 Argon2id 哈希。
- 256-bit 随机 `HttpOnly` Session Cookie 和登录限流。
- 创建、加入和开始房间；每局最多 12 人。
- 服务器控制的 5 秒同步回合。
- 直接出招和合成出招；合成材料按具体实例消费一次。
- 单体攻击、龙波和镰刀群攻、闪避方向、攻击转防御、护、盾及持续防御。
- 网络动作运行时校验，以及基于 `actionId` 的幂等重试。
- 相同游戏状态和动作输入产生确定的结算结果。

当前限制：

- 活跃房间只保存在单个服务器进程的内存中；服务器重启会终止进行中的对局。
- 用户和 Session 存储在 SQLite 中，数据库调用目前仍位于服务器应用内，尚未抽象为可替换的持久层。
- 尚未实现匹配、观战、战绩、管理员功能和生产监控。
- 未提交回合动作的玩家视为空过。

## 本地运行

需要 Node.js 22 LTS 或 Node.js 24 LTS，推荐 Node.js 24 LTS。

安装依赖并执行验证：

```bash
npm install
npm test
npm run build
```

在第一个终端启动服务器：

```bash
npm run dev
```

在第二个终端启动 Web：

```bash
npm run dev:web
```

访问 `http://localhost:5173`。Vite 开发服务器会把 `/api` 和 `/socket.io` 代理到 `http://localhost:3000`。

## 配置

| 环境变量       | 默认值                  | 说明                                                                  |
| -------------- | ----------------------- | --------------------------------------------------------------------- |
| `PORT`         | `3000`                  | HTTP 和 Socket.IO 服务端口。                                          |
| `DB_FILE`      | `game.db`               | SQLite 数据库文件路径。                                               |
| `WEB_ORIGIN`   | `http://localhost:5173` | 允许携带凭证访问服务器的 Web Origin。                                 |
| `NODE_ENV`     | 未设置                  | 设置为 `production` 时，Session Cookie 启用 `Secure`。                |
| `VITE_API_URL` | 空                      | 浏览器连接的服务器地址。为空时使用当前 Origin；本地开发由 Vite 代理。 |

生产环境必须使用 HTTPS，并准确设置 `WEB_ORIGIN`。如果Web和服务器不同源，还需要在构建Web时设置 `VITE_API_URL`：

```bash
VITE_API_URL=https://api.example.com npm run build
```

不要把 `.env`、数据库文件或真实凭证提交到仓库；它们已列入 `.gitignore`。

## 回合与网络行为

浏览器提交的动作包含 `gameId`、`round`、`actionId`、出招内容、可选目标和攻击转防御点数。玩家身份不接受客户端声明，只从已经验证的Socket连接取得。

服务端在接受动作时校验当前回合、招式、目标和合成材料。相同 `actionId` 的网络重试返回首次提交结果，不会重复出招；同一玩家使用新的 `actionId` 重复提交会被拒绝。

回合截止后，服务器使用提交时已经准备好的动作统一结算。若发生内部状态错误，服务器会记录错误、暂停该局并通知房间，而不是静默丢弃玩家动作。

## 当前结算约定

- 已锁定动作即使玩家在同一回合死亡仍然生效。
- 多个单体攻击先求和并消耗同一防御池；群攻只取最高值，再使用剩余防御。
- 群攻不攻击施放者本人。
- 招式存在任意配方路径包含冲拳、旋风或左右波时，分别覆盖下地、上天或左右。
- 等价运数至少为 4 的攻击覆盖全部闪避方向。
- 当同一招式的合法配方能级不一致时，采用最大的等价运数。
- 铜墙铁壁的一次性抵伤在全部攻防计算之后、扣除护甲和死亡判定之前结算；最终伤害大于 0 时抵挡 1 点并立即消失。
- 盾系只有在防御没有被击穿时才获得全额护甲；被击穿时不获得新护甲。
- 护甲恰好降到 0 时仍然存活，低于 0 才死亡。

完整招式及配方位于 `packages/game-data/src/index.ts`。

## 代码风格

- 代码标识符使用英文。
- 代码注释、文档、UI和面向玩家的错误消息使用中文。
- 代码中的类型名、字段名、环境变量及其他字面量保留原名。
- 注释只解释不直观的规则原因、顺序约束和失效条件，不复述代码操作。

格式化代码：

```bash
npm run format
npm run format:check
```
